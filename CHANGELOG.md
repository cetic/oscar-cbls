# Changelog

This file documents changes in the OscaR.cbls project.
## [6.1.1] - 2026-09-04
### Fixed
 - Fix a bug in the CI/CD script that prevented the public publishing of the 6.1.0 release.

## [6.1.0] - 2026-09-03
### Added

- `DistributedPopulationBased`: a distributed counterpart of the `PopulationBasedSearch` combinator, which spreads the exploration of a population of solutions over the workers of a distributed search.
- Examples of the `DistributedPopulationBased` combinator, for both the warehouse location and the vehicle routing problems, in single-JVM and multi-JVM flavours.
- `MultiJVMExampleRunner`: a single entry point to launch the multi-JVM examples, together with an sbt-assembly based mechanism to build the standalone "fat jar" they run from.
- Documentation of the distributed search architecture (`docs/DistributedSearchArchitecture.md`).
- `DistributedSearch.waitForWorkers`: blocks until the requested number of workers registered to the supervisor, or until a timeout elapses, and reports how many did register. It relies on the new `WaitForWorkers` message of the supervisor and replaces the `Thread.sleep` that the multi-JVM examples used to wait for remote workers.

### Changed

- The seed of the data generate is now an `Option[Long]` instead of a `Long`.
- The runnable examples now parse their command line with `scopt`, which gives them a `--help` option and proper validation. The hand-written `oscar.cbls.util.ArgParser` has been removed.
- The `DoAllMoves` task now carries the single objective that must drive the exploration, instead of an objective plus an alternate one that would override it. Its optional second objective, `objectiveToMeasureOpt`, is only evaluated on the solution that is reached and reported back alongside the first one.
- Replaced the StdIn-based workaround with `OscaRDisplay.waitForClosing()` so the process now exits automatically when the visualization window is closed.
- Routing visualizations now draw directional arrows instead of plain lines to show the direction of travel along each route.
- Route colors are now generated by evenly spacing hues around the color wheel (instead of random RGB), with a background-aware variant for the OpenStreetMap-based geographic display, to keep vehicle routes visually distinguishable.

### Fixed
- The output's size of the `RouteLentgh` invariant
- The `DistributedPopulationBased` VRP examples used to draw an unseeded `Random` to build their initial routing, which is done once per node (multi-JVM) or once per worker (single JVM), so the supervisor and the workers all started from a different initial solution and compared solutions that were not built on comparable models. The initial solution is now built from a fixed seed, carried by the problem statement in the multi-JVM case, while the randomness that only diversifies the exploration stays unseeded.

## [6.0.0] - 2026-03-26

Refactoring of the OscaR.cbls library.

### Refactor

- Refactoring the core of OscaR.cbls:
  - Propagation structure
  - Main variable types:
	- IntVariable: Variable type that contains integer
	- SetVariable: Variable type that contains set of integers
	- SeqVariable: Variable type that contains an ordered sequence of integer
  - Abstract constraint structure
  - Abstract neighborhood structure
  - Abstract objective structure
- Refactoring the main invariants based on the abstract constraint structure
  - Main integer invariants (e.g. sum of an array of IntVariable, min/max of an array of IntVariable, basic operations on IntVariables (sum, minus, prod and div), etc.)
  - Main set invariants: (e.g. cardinality of a SetVariable, intersection, union and difference of SetVariable, etc.)
  - Main seq invariants: (e.g. content of a SeqVariable, size of a SeqVariable, etc.)
  - Main routing invariants (e.g. length of a route, number of nodes in a route, time windows, etc.) + Abstract structure for symbolic global constraint
- Implementation of a generic test bench for invariants
- Refactoring neighborhoods:
  - Main neighborhoods on IntVariable arrays (e.g. assign value, swap values, etc.)
  - Main routing neighborhoods (e.g. moving one point, two opt, three opt, insert nodes, etc.)
- Refactoring combinators for metaheuristics (e.g. best neighborhood first, cartesian products of neighborhoods, restarts, etc.)
- Refactoring multi-thread optimization (BETA) with distributed search heuristics (e.g. distributed modulo)
- Refactoring the api of the library
- Refactoring visualization primitives to help modeling problems
